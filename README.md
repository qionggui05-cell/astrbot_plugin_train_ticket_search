# AstrBot 火车票查询插件（astrbot_plugin_train_ticket_search）

一个基于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) v3.x 的 QQ 机器人火车票查询插件，支持**聚合数据（juhe.cn）** 与 **接口盒子（apihz.cn）** 两种真实数据源，支持锁定车次、余票提醒、缓存快查与强制更新。

核心指令：

1. **查票**（`/火车票 查票`）：交互式询问目标日期、出发站、到达站，展示车次与各席别票价（含已售罄车次）；
2. **余票提醒**（默认开启）：锁定车次后，**全部席别余票合计**低于阈值（默认 10 张）时自动推送提醒；任一席别余票显示为"有"按大量（>10 张）计；可用 `/火车票 余票提醒 关 [车次号...] [日期]` 关闭；
3. **快查**（`/火车票 快查`）：读取最近一次刷新保存的价格，**不调用 API**；
4. **强制更新**（`/火车票 强制更新`）：立即调用 API 刷新所有已锁定车次的价格。

已发车（出发时刻已过）的锁定车次会被**自动解除锁定**：定时刷新时静默清理；调用 `/火车票 快查` 时会提示"您关注的车次已发车，已将其自动解除锁定"。

每次输出车次信息结果（查票/快查/强制更新）都会附带**数据更新时间**与**今日 API 调用次数**；`/火车票 我的` 只显示锁定车次与余票提醒开关状态。
锁定车次列表（快查/我的/锁定确认）会**按发车时间排序并编号**（先按日期、再按发车时刻）。

## API 与调用次数说明

### 数据源一：[聚合数据](https://www.juhe.cn/)（`data_source=juhe`）

使用聚合数据「火车订票查询」接口：

```
GET https://apis.juhe.cn/fapigw/train/query
    key=你的APIKey
    search_type=1（按站点名称）或 2（按站点编码）
    departure_station=出发站（如 北京南 / VNP）
    arrival_station=到达站（如 苏州北 / OHH）
    date=YYYY-MM-DD（仅限未来 15 天内）
    enable_booking=2（全部班次，含已售罄车次，便于监控余票回升）
```

该 API 每日调用次数有限（示例 Key 为每日 10 次）。

### 数据源二：[接口盒子](https://www.apihz.cn/)（`data_source=apihz`）

使用接口盒子（apihz.cn）的 12306 接口（免费、无每日上限）：

```
余票信息查询  https://cn.apihz.cn/api/12306/api.php
公示票价查询  https://cn.apihz.cn/api/12306/api4.php
    参数：id=开发者ID  key=开发者KEY  add=出发站  end=到达站
         y=年  m=月  d=日
```

余票返回 `seats[].stock`：`-1`=有票充足（显示为“有”）、`0`=无票、`>0`=余票数量；票价来自公示票价接口，与余票合并展示。

> ⚠️ **价格说明**：接口盒子的价格为未打折价格，如 12306 的价格为 679 元（7.8 折），接口盒子返回的价格为 870 元，一切价格以购票处实际为准。

席别展示规则（按车次类型白名单过滤）：
- 每种车次类型只展示其真实存在的席别：**G**=二等座/一等座/商务座/无座；**D**=二等座/二等卧/一等卧/无座（接口原名的 硬卧/软卧 会按动车习惯显示为 二等卧/一等卧）；**K/Z/T**=硬座/硬卧/软卧/无座；
- 名单内的席别只有**有余票**或**票价已知**才展示；名单外的席别仅在接口明确报出余票时兜底展示（不漏掉真实余票）。余票接口对不存在席别返回的 stock=0 幽灵席别（无票且无价）一律过滤，不再刷屏；
- 票价未知的席别不再显示“¥0”：无价席别只显示余票状态（如 `一等卧[余票 无]`），跟踪席别查不到价时显示“票价待查/暂无报价”；
- 公示票价接口（api4）不返回“无座”票价，插件默认开启 `apihz_use_detail_price`，
  对“有余票但公示票价缺失”的席别按车次调用余票票价接口（api2）补查真实票价；
  每次查询最多补查 8 个车次（`apihz_detail_price_max_calls`），触发接口频次限制后自动停止；
- 补查仍拿不到票价时，有余票的无座按同车次硬座/二等座票价兜底，不再显示 0 元。

出发日期统一使用**查询日期**：接口返回的 `datas.date` 对部分车次（如凌晨发车的 D114）
会错位成前一天，导致锁定/提醒/快查显示的日期错误，插件已改为以用户查询的日期为准。

### 调用策略（两种数据源通用）

| 场景                            | 是否调用 API     |
| ----------------------------- | ------------ |
| 定时自动刷新（默认每 4 小时一次）            | 是（仅在有锁定车次时）  |
| 启动时刷新（`startup_refresh`，默认开启） | 是（仅在有锁定车次时）  |
| `/火车票 强制更新`                   | 是            |
| `/火车票 查票`（交互查询）               | 是（每次查询消耗一次；接口盒子为余票+票价各一次） |
| `/火车票 快查`（获取价格）               | **否**，只读本地缓存 |
| `/火车票 我的` / `/火车票 帮助`         | 否            |

每次刷新/强制更新后，价格会立即写入 `data/locks.json` 保存，重启不丢失；`/火车票 快查` 展示的就是最近一次保存的价格。同一时刻只允许一个刷新任务运行，启动/定时/强制刷新重叠时不会重复调用 API。

余票提醒覆盖**所有已锁定车次**：余票为 0（全部席别售罄）的车次同样参与提醒；
定时刷新时若某条线路查询成功但结果中未返回已锁定车次（如已售罄未列出），
也会按余票 0 处理并提醒，避免漏报。线路整组查询失败时保留旧数据、不误报。

> 注意：聚合数据接口只支持查询**未来 15 天内**的日期；查询超过范围会返回友好提示。

## 配置 API Key（重要）

插件在 `_conf_schema.json` 中暴露了 `juhe_appkey`、`apihz_id`、`apihz_key` 等配置项（**默认值均为占位符 `xxxxxxx`**，必须由你自己填写）：

1. 将插件放入 AstrBot 插件目录后，进入**管理面板 -> 插件配置**；
2. 找到 **聚合数据火车票查询API Key（juhe_appkey）**；
3. 把默认的 `xxxxxxx` 替换为你自己申请的 Key/ID 并保存。

> 未填写或仍为占位符时，`/火车票 查票`、定时刷新和强制更新都会提示先配置，不会发起请求。

如需切换接口地址，可修改 `juhe_api_url`、`apihz_api_url`、`apihz_price_url`。

## 安装

1. 根据Astrbot的插件安装方式（压缩包/项目链接）进行安装；
2. 重启 AstrBot（或重载插件）。首次加载时 AstrBot 会自动安装 `requirements.txt` 中的依赖（`apscheduler` 用于定时刷新；`requests` 用于请求聚合数据接口）；
3. 在管理面板确认插件已启用，并**填入你自己的数据源凭据**（默认 `xxxxxxx` 只是占位符）。

## 指令说明

| 指令                             | 说明                                             |
| ------------------------------ | ---------------------------------------------- |
| `/火车票 帮助`                      | 显示帮助                                           |
| `/火车票 查票 [类型...]`              | 交互式查票。可选类型过滤，如 `/火车票 查票 G D`；默认全部类型            |
| `/火车票 锁定 <车次号...>`             | 锁定查询结果中的车次（多个用空格分隔），锁定后**默认开启余票提醒**            |
| `/火车票 余票提醒 <开/关>[车次号...] [日期]` | 开/关所选车次号的余票提醒；日期可选，如 `/火车票 余票提醒 关 G25 2026-08-07` |
| `/火车票 快查`                      | 直接返回已锁定车次的缓存价格与全部席别余票（不调用 API）；已发车车次会自动解除锁定并提示 |
| `/火车票 强制更新`                    | 立即调用 API 刷新所有已锁定车次价格并展示结果                      |
| `/火车票 解锁 <车次号...> [日期]`        | 解锁车次                                           |
| `/火车票 我的`                      | 查看我的锁定车次与提醒设置                                  |
| `/火车票 数据源 [名称]`                | 查看当前数据源；带 `juhe`/`apihz`/`demo` 参数时切换数据源（全局生效，重启保留） |

支持的车次类型：`G` 高铁、`D` 动车、`Z` 直达特快、`T` 特快、`K` 快速、`O` 其他。

### 交互式查票示例

```
用户: /火车票 查票
机器人: 请输入目标日期（今天/明天/后天 或 YYYY-MM-DD，聚合数据接口限未来 15 天内）：
用户: 明天
机器人: 请输入出发站（如：北京南，也可输入站点编码如 VNP）：
用户: 北京南
机器人: 请输入到达站（如：苏州北）：
用户: 苏州北
机器人: ===== 2026-08-03 车次与票价 =====
        【高铁(G)】
          G25 北京南 18:04 → 苏州北 22:32（历时 04:28） 二等座 ¥627[余票 1]
              一等座 ¥1003[余票 无] · 商务座 ¥2194[余票 无]
        提示：回复 /火车票 锁定 <车次号> 可锁定车次（多个车次号用空格分隔）。
用户: /火车票 锁定 G25
机器人: 已锁定以下车次：
          ...
用户: /火车票 余票提醒 关 G25
机器人: 已为 1 个锁定车次关闭余票提醒。
```

多轮交互过程中随时可回复 **取消** 退出；会话 10 分钟无进展自动过期。锁定操作基于**最近一次查询结果**，请先查票再锁定。

查询接口瞬时失败（如接口盒子返回“失败，请重试!”）时，机器人会保留你已输入的
日期/出发站/到达站并提示回复 **重试**：回复「重试」即按上次输入原样再次请求，
也可以直接输入新的到达站后重新查询。

### 快查示例（全部席别 + 时刻信息）

```
用户: /火车票 快查
机器人: ===== 已锁定车次价格（缓存） =====
        08-07 D114 西安 00:33 → 上海松江 16:23 ：二等卧 ¥400[余票 无] · 二等座 ¥240[余票 无] · 一等卧 ¥596[余票 3] · 无座 ¥240[余票 无]，余票提醒：开（<10张）
        08-07 G3286 西安北 11:41 → 上海虹桥 19:42 ：商务座 ¥2068[余票 14] · 一等座 ¥1062[余票 4] · 二等座 ¥666[余票 无] · 无座 ¥666[余票 有]，余票提醒：开（>10张）
```

`余票提醒：开（<10张）` 表示全部席别余票合计低于 10 张（即将触发提醒）；`开（>10张）` 表示合计不低于 10 张（充足）。余票提醒关闭时同样会显示合计余票状态，如 `关（>10张）`。

## 配置项（管理面板 -> 插件配置）

| 配置                           | 默认值                                       | 说明                                                  |
| ---------------------------- | ----------------------------------------- | --------------------------------------------------- |
| `data_source`                | `juhe`                                    | 数据源类型：`juhe`（聚合数据）、`apihz`（接口盒子，免费无上限）或 `demo`（演示数据） |
| `juhe_appkey`                | `xxxxxxx`（占位符）                            | 聚合数据火车票查询 API Key，**必须由用户自行填写**                     |
| `juhe_api_url`               | `https://apis.juhe.cn/fapigw/train/query` | 聚合数据接口地址                                            |
| `apihz_id`                   | `xxxxxxx`（占位符）                            | 接口盒子开发者 ID（apihz.cn 后台个人资料），**必须由用户自行填写**           |
| `apihz_key`                  | `xxxxxxx`（占位符）                            | 接口盒子开发者 KEY，**必须由用户自行填写**                           |
| `apihz_api_url`              | `https://cn.apihz.cn/api/12306/api.php`    | 接口盒子 12306 余票信息查询接口地址                               |
| `apihz_price_url`            | `https://cn.apihz.cn/api/12306/api4.php`   | 接口盒子 12306 公示票价查询接口地址                               |
| `apihz_use_detail_price`     | `true`                                    | 启用余票票价补查（公示票价缺失但有余票时按车次调用 api2 补查票价）          |
| `apihz_detail_price_url`     | `https://cn.apihz.cn/api/12306/api2.php`   | 接口盒子 12306 余票票价查询接口地址                               |
| `apihz_detail_price_max_calls` | `8`                                     | 每次查询 api2 补查的最大车次数（免费用户接口约限频 10 次/分钟）         |
| `apihz_cookie`               | 空                                         | 接口盒子可选 cookie（JSESSIONID），查询失败时可自行填写                 |
| `refresh_interval_hours`     | `4`                                       | 定时刷新间隔（小时），机器人启动时也会自动刷新一次                           |
| `startup_refresh`            | `true`                                    | 启动时是否自动刷新一次（有锁定车次时才调用 API）                          |
| `ticket_alert_threshold`     | `10`                                      | 余票提醒阈值（张），锁定车次默认开启余票提醒                              |
| `max_locked_trains_per_user` | `20`                                      | 每个用户最多可锁定的车次数                                       |
| `demo_override_file`         | 空                                         | 演示数据价格覆盖文件（JSON），留空则使用插件 `data/demo_overrides.json` |

演示数据覆盖文件支持两种格式，可同时使用：

**1. 测试车次（推荐）**：按日期+车次号精确匹配，命中后完全替代该类型该日期的生成车次；`depart`/`arrive` 可选，缺省时对任意线路生效：

```json
{
  "flights": [
    {
      "date": "2026-08-05",
      "train_type": "G",
      "train_no": "G9801",
      "depart_time": "16:45",
      "arrive_time": "19:35",
      "duration": "02:50",
      "price": 460,
      "depart": "北京南",
      "arrive": "苏州北"
    }
  ]
}
```

**2. 旧格式价格覆盖**：按车次号覆盖演示价格（对任意线路/日期生效）：

```json
{
  "G9801": 560,
  "D3201": 480
}
```

## 数据文件

- `data/locks.json`：用户锁定车次与提醒设置，JSON 持久化，重启不丢失；文件损坏时会自动备份为 `locks.json.corrupt-<时间戳>` 并重建。
- `data/runtime_config.json`：聊天指令 `/火车票 数据源` 切换后保存的数据源名，优先于管理面板配置，重启后仍生效。
- `data/demo_overrides.json`：可选的演示价格覆盖文件（首次运行时自动创建 data 目录）。

## 开发与测试

核心逻辑（数据源、提醒引擎、存储、格式化、会话流程）与 AstrBot 解耦，可独立运行单元测试：

```bash
pip install -r requirements.txt pytest
python -m pytest tests/ -v
```

运行环境要求：Python 3.10+、AstrBot v3.x。
